- **Point-in-time snapshots for paginated offline exports (#1772).** Backing up a
  live database with offset pages was racy: rows a background agent wrote mid-export
  shifted later pages (so records showed up twice), and rows it soft-deleted vanished
  from the backup. New `POST /api/export/snapshots` pins one instant — membership is
  frozen in `export_snapshot_rows`, so later inserts are excluded and later deletes
  stay in the backup — and `GET /api/export/snapshots/{id}/pages` walks the pin with
  an id keyset cursor that can neither skip nor repeat a row when resumed. Pins live
  one hour (`MCP_EXPORT_SNAPSHOT_TTL_SECONDS`); reading an expired pin now returns
  **410 Gone** with an explicit instruction to start a new export, instead of silently
  serving a half-changed result. `DELETE` releases a pin early. sqlite-vec only for
  now; other backends answer 501.
