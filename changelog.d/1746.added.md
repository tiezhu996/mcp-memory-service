- **Canonical tag aliases: register the spellings a team actually uses under one primary tag (#1746).**
  Prefixes, bare project names and capitalization variants scattered one logical tag
  across search results and counts. New MCP tools `tag_alias_register`, `tag_alias_list`
  and `tag_alias_remove` (plus `GET/POST/DELETE /api/tags/aliases`) maintain a mapping
  that lives in a backend-independent `tag_aliases.json` under the data directory
  (`MCP_TAG_ALIASES_PATH` overrides), so registrations survive restarts and
  sqlite-vec/Cloudflare/Milvus/hybrid backend switches. New writes are stored under the
  canonical tag; old rows are never rewritten but query/delete expand to every variant
  (correct ANY/ALL grouping) and tag listings, usage counts and returned tag views merge
  onto the canonical tag. Removing a registration undoes the virtual merging without
  touching memories. Delta-sync still applies remote events verbatim.
